## Result

- **Check passes.** `138fb64` (slice 05) is 73% moved and `fc3f4a6` (slice 06) 76% moved under `allow-indentation-change`. Under the default whitespace setting both fail (513 new vs 127 moved; 166 vs 160).
- **Indentation is the whole difference.** Commits whose moved code kept its indentation (`9083e81`, `596eacd`) count the same either way. The ones that moved code into a function body (slices 02, 04, 05, 06) only show as moved when indentation changes are ignored.
- **The whole range counts fewer lines as new than the commit rows do:** 538 vs 583 summed (moved 1,254 vs 1,408). A block a branch deletes in one commit and re-adds elsewhere in a later one is new in the later row but moved in the range diff. So the range diff is the right number for the PR total.
- **This spike counts docs too.** The scorecards (`fbf78f7`, `5ddb658`, 133 lines) and `AGENTS.md` (3 lines) are in these numbers; slice 03's filter skips non-code files, so the product-code PR total will be lower, roughly 400.

- **Zebra vs plain mode matters.** The independent check found `--color-moved=plain` gives 133 new for `138fb64` and 392 for the range. The cause isn't confirmed yet (slice 02 should find it). Zebra is the stricter count (more lines stay "new"); slice 02 should keep it unless the user prefers the looser one.
- **What "new" still includes:** real changes (the router fix in `138fb64`, the new `shared.ts` types in `ea9b3ed`), import lines, and short moved lines below git's block-size floor (20 alphanumeric characters per block). So it leans high, not low.
